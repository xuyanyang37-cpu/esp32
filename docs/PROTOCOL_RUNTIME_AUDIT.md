# 协议运行逻辑与接口审计

## 数据调用链
1. BLE 通知进入 `BmsBle` 接收回调。
2. 通知被拼接到接收缓冲区并清理噪声/ACK。
3. `BmsProtocolManager::findFrameStart()` 查找最早的候选帧头。
4. `frameLength()` 使用候选协议计算当前帧长度。
5. 收到完整帧后调用具体协议解析器。
6. 解析成功才提交活动协议；无效帧不应改变后续查询命令使用的协议。
7. 解析后的 `BmsData` 被显示层和网页配置层读取。

## 已集成修正
- 将当前候选帧解析器与活动协议分离。
- TT 变长帧计算支持 Modbus 正常响应、异常响应，以及受长度上限约束的 EF 私有帧。
- JK TLV 解析保留 MAC、网页配置、启动状态等本机字段，并重置遥测字段以避免沿用旧帧数据。

## 未完成项
- JBD、DALY 仍为占位实现，不应宣称协议已经支持。
- ANT 已按公开的 2021+ 状态帧布局修正电池运行状态与均衡状态：充/放电来自 p[7] 的状态码，均衡状态码只有 0x04 才表示开启；总压、电流、SOC、MOS 状态和容量偏移与公开实现对照。仍需用本机保护板原始 BLE 通知核对固件差异、温度传感器数量和各字段实际倍率。
- TT 的寄存器映射、单位缩放和 EF 私有帧格式需实测。
- 彦阳 Modbus 从站地址、寄存器起始位置/数量、CRC 与缩放需实测。
- CI 只检查编译/链接，不检查 BLE 连接、屏幕显示、断线恢复或协议数据准确性。

## 硬件验收建议
1. 保存 BLE 原始十六进制通知，覆盖拆包、粘包、噪声前缀与重连。
2. 每种协议核对帧头、长度、CRC/校验和与解析结果。
3. 对照原厂 App 检查总压、电流方向、SOC、电芯数量、温度与容量单位。
4. 验证无效帧不切换协议，断线后只有收到有效数据才恢复状态。
5. 验证热点模式不重复创建服务器或反复分配 BLE 客户端。
